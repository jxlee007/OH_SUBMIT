## **8-HOUR vs 24-HOUR HACKATHON STRATEGY**

### **8-HOUR VIRTUAL ROUND (Oct 31)**

```
0:00-0:15  (15 min) PLANNING
├─ Read problem statement carefully
├─ Sketch architecture (1 diagram: modules, data flow)
├─ List 2-3 achievable features (not 10)
└─ Decision: REST API design + database schema

0:15-6:00  (5h 45min) BUILD CORE FEATURE ONLY
├─ 1 complete flow: Input → Process → Output
├─ Example: Create Order → Save to DB → Return JSON
├─ Include basic validation + error handling
└─ NO extra features, NO polish

6:00-7:00  (1 hour) TESTING + SHIPPING
├─ Test 3 scenarios (happy path + 2 edge cases)
├─ Deploy to Render/Railway (1 click)
├─ Push code to GitHub with meaningful commit messages
└─ Record video: "Here's what I built and why"

7:00-7:30  (30 min) PRESENTATION
├─ 2-minute demo (working app)
├─ 2-minute explanation (architecture + decisions)
└─ Answer judges: "Why this design?"
```

**Rule:** Ship working → tested → documented. NOT pretty OR complete.

---

### **24-HOUR FINAL ROUND (Dec 12-13)**

```
0:00-1:00  (1 hour) ARCHITECTURE SPRINT
├─ Design Clean Architecture (Entity → UseCase → Repository)
├─ Draw database schema (relationships, indexes)
├─ Define API contracts (request/response formats)
├─ List domain rules (business logic)
└─ Setup: Database, Prisma, auth, project structure

1:00-18:00 (17 hours) BUILD 2 COMPLETE FLOWS
├─ Flow 1: 60% effort (main feature)
│  └─ Working end-to-end, tested, deployed
│
├─ Flow 2: 40% effort (secondary feature)
│  └─ Same quality: working, tested, deployed
│
└─ Time allocation per flow:
   - Coding: 70%
   - Testing (unit + integration): 20%
   - Deployment + docs: 10%

18:00-23:00 (5 hours) POLISH + VIDEO
├─ Write README (what this does, how to run it)
├─ Make Git history clean (meaningful commits)
├─ Record demo video (3-4 min: here's the app working)
├─ Prepare 1-slide architecture diagram
└─ Practice pitch: "What I built, why, what it proves"

23:00-24:00 (1 hour) FINAL PRESENTATION
├─ Live demo (both flows working)
├─ Architecture explanation (3 min)
├─ Answer questions confidently
└─ Show code: "This is how I separated concerns"
```

**Rule:** 2 flows shipping > 1 flow half-built. Quality matters more than quantity.

## **WHAT CHANGES FROM YOUR 8-WEEK PREP**

| Phase | 8-Week Prep | 8-Hour Hackathon | 24-Hour Hackathon |
|---|---|---|---|
| Architecture | 3 days (detailed) | 15 min (minimal) | 1 hour (solid) |
| Testing | 20% effort | Skip unit tests, do manual | 20% effort (pytest) |
| Features | 5+ complete | 1 complete | 2 complete |
| Documentation | README + comments | 1-line comments | README + inline docs |
| Deployment | Local + Render | Render | Render + GitHub |
| Polish | High | Minimal | Medium |

---

## **KEY DIFFERENCE: FOCUS**

**Your 8-Week Prep:** Learn architecture, testing, communication → ship portfolio projects  
**Hackathon:** Ignore learning, focus on **shipping ONE working thing** judges can see

**Winning logic:**
```
1 fully working feature (code + tests + docs + deployed) 
= Beats 5 features that are 40% done

Judges see:
✅ You can code independently (no AI dump)
✅ You understand separation of concerns (clean code)
✅ You can ship under pressure (deployed URL works)
✅ You communicate decisions (video explanation)
✅ You test your own code (didn't crash on edge case)
```

## **COMPRESSED CHECKLISTS**

### **8-Hour: Minimal MVP**
```
☐ Problem understood (1 sentence)
☐ 1 database table with proper schema
☐ 1 API endpoint (POST or GET working)
☐ 1 form or UI (sends data to API)
☐ Validation (rejects bad input)
☐ Error message (tells user what went wrong)
☐ Git: 5+ commits with messages
☐ Deployed (URL works from phone)
☐ Video: Demo in 90 seconds
```

### **24-Hour: 2-Feature Product**
```
☐ Architecture diagram (2 min to explain)
☐ Clean code structure (Entity/UseCase/Repository visible)
☐ Database schema (normalized, indexes)
☐ Feature 1: Full CRUD (Create, Read, Update, Delete)
☐ Feature 2: Secondary workflow (maybe reporting, search, filtering)
☐ Tests: Each feature has 3+ test cases
☐ Error handling: 400/404/500 responses correct
☐ Authentication: Protected endpoints if required
☐ Deployment: Zero downtime, works live
☐ Documentation: README explains everything
☐ Git: 15+ meaningful commits
☐ Video: 4-min demo + architecture explanation
```

- **24h hackathon:** 1h plan → 17h build 2 features → 5h polish+video → 1h present
